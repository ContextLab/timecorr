## About This Project

timecorr is a Python toolbox for computing and exploring correlational structure in timeseries data. The `timecorr` function computes kernel-weighted dynamic correlations from timeseries observations, and `features` computes higher-order dynamic correlations through the two-path pipeline of Owen, Chang & Manning (2021), Fig. 10 (by default with Gaussian kernels whose widths are set from each order's input and squared-correlation summaries at orders >= 2; the original pipeline is selected with `rfun="PCA", delta_rfun=None, delta_weights_function=tc.eye_weights`). With `causal=True` (version 0.4.0) both compute row `t` from rows `0..t` only, with reducers fitted on the first `fit_timepoints` rows and returned as a `tc.FeaturesModel`.

## Code Architecture

### Core Components

- **`timecorr/timecorr.py`**: the `timecorr()` function, the primary entry point for computing dynamic correlations (or, with `cfun=None`, kernel-weighted smoothing). Keyword-only `causal`, `min_samples`, `fit_timepoints` (see "Causal mode" under Key Concepts): `_causal_arguments` checks what has no causal form, `_causal_smooth` is the smoothing of `cfun=None` with NaN warm-up entries per feature (each chunk's samples centered on the weighted mean of its first row, which is added back), `_needs_fit` says whether an `rfun` is fitted to data, `_check_fit_timepoints` validates `fit_timepoints`, and `_fit_reducer` fits a reducer on the rows without any NaN or infinite value and returns what is applied frozen (a `summaries._FittedSummary`, a `helpers._FittedModel`, or the reducer itself when nothing is fitted).
- **`timecorr/_kernels.py`**: `LagKernel`, the kernels of `timecorr`, `features`, `two_path_step`, the streamed summaries and the decoders for the built-in kernel functions: the lag profile (length T; the kernel functions in `helpers` build their T x T matrices from the same profile functions), `include_timepoints`/`include_zero`/`exclude_timepoints` and the event labels (`events.mask_kernel` accepts it), with `block(t0, t1, c0, c1)`, `span(t0, t1)` and `key(t0, t1)` (chunks away from edges and event boundaries share one block; `with_events` intersects the events it already has, `with_events(None)` keeps them; labels are runs of consecutive values, a single block stored as None; a non-finite `exclude` raises `ValueError`, as `exclude_timepoints` does for every kernel function); no T x T array is built (`uniform_weights` and `eye_weights` build their dense output directly). A kernel function of the user's gives T x T arrays (`helpers._lag_kernel` returns None for it), wrapped in `ArrayKernel` (the same `shape`/`chunks`/`block` interface; every chunk spans all columns; blocks are read-only views); `as_kernel` wraps either, and `blocks(kernel, size, transform, full)` is the one chunk iterator (blocks computed once per key), used by the estimator, the smoothing of `timecorr` and the row statistics. A custom `cfun` receives T x T arrays (counted by the memory guards and by `estimate_memory_gb(..., cfun=)`; a feeding kernel of the user's counts only at the orders whose feeding path runs).
- **`timecorr/helpers.py`**:
  - Kernel functions (`gaussian_weights`, `laplace_weights`, `eye_weights`, `mexican_hat_weights`, `t_weights`, `uniform_weights`, `boxcar_weights`) and `one_sided`
  - The estimator `wcorr` and correlation functions (`isfc`, `wisfc`, `autofc`), each with keyword-only `causal=False, min_samples=None`; the causal branch is `_causal_setup` / `_causal_block` (see "Causal mode" under Key Concepts)
  - Frozen hypertools models of causal mode: `_model_reduce(..., return_model=True)` gives a `_FittedModel` (the model, its padding and its frozen constant columns); `_COMPONENT_MODELS` names the models with `components_`; `_FitUnusable` is raised for a fit a refit cannot use
  - Combine functions (`null_combine`, `corrmean_combine`, `mean_combine`, `tstat_combine`)
  - `reduce` (dimensionality reduction), `format_data` (input formatting via pydata-wrangler), `mat2vec`/`vec2mat`, `smooth`, `plot_weights`
  - Re-exports of the decoders from `decoding.py`
- **`timecorr/higher_order.py`**: the two-path pipeline: `features`, `two_path_step`, `estimate_memory_gb` (`streamed=True` for the peak of a streamed step; `combine=` counts the temporaries of the built-in combine functions, not of a function of your own). Keyword-only `delta_weights_function` / `delta_weights_params` set the kernel of the delta (feeding) path (default None: `gaussian_weights`, giving `autofc` correlations; `eye_weights` gives co-fluctuations). Kernel parameters of None (the defaults `weights_params=None`, `delta_weights_params=None`) with Gaussian kernels on both paths are automatic (`_auto_sd`, `_auto_params`): at each order the feeding kernel's standard deviation is 5 autocorrelation widths of that order's input, at least 5 rows and at most a hundredth of its rows or 5 rows, whichever is larger (so 5 below 500 rows), and the analysis kernel's is that or 10 rows, whichever is larger (white data: 10 and 5 at order 1, the fixed kernels of earlier versions, which are requested with `weights_params={"var": 100}, delta_weights_params={"var": 25}`; recordings of up to 1000 timepoints: at most 10 samples at every order). With no kernel parameters and no events given and two-sided kernels (`include_timepoints="all"`), `features` passes each order's feeding features on at every `floor(sd / 2)`-th row while at least 1000 rows remain and returns every output at all timepoints by linear interpolation (`return_info` entries of automatic kernels have `kernel_sd` and `sampling`). With another kernel function, or `eye_weights` on the feeding path, None is that function's own defaults. `weights_params` / `delta_weights_params` also accept order maps (dicts whose keys are all integers in 1..order; missing orders use the default; `two_path_step`, exported as `tc.two_path_step`, raises for one). `rfun` / `delta_rfun` accept `"auto"` (the defaults; analysis: PCA at order 1, `WeightedStrength(signed=True)` above; feeding: `Communities()`, which needs >= 4 features and T >= 40 (with more features than distinct shift-null lags in `[L, T - L]`, each lag is used for several features, balanced, and features sharing a lag keep their dependence in that surrogate; for a built-in kernel without events, one-sided restriction or `exclude_timepoints` (`summaries._stationary`) the null's squared correlations are averaged over every s-th timepoint, s the kernel's standard deviation rounded down for a Gaussian: `summaries._null_row_stride`; for any other kernel (arrays, kernel functions of your own, restricted kernels), over every timepoint); when its communities would emit fewer than 4 columns, the step emits `WeightedStrength(split=False, signed=False, center=False)` instead, one column per input feature, warning only when the shift null found no structure) and dicts keyed by order. `return_info=True` returns `(result, info)` with one dict per step and path (reducers requested and used, widths, community counts, fallback reason; no arrays, but lists of ints: `"constant_columns"` in every entry, the output columns with `np.ptp(x, axis=0) == 0` in the returned arrays (after the interpolation to all timepoints; one list per subject for list outputs; for feeding features that are not returned, in the rows computed), and `"labels"` in feeding entries, the community of each input column when the step's output columns are the communities of a `Communities` object (the default's included), None after a fallback, for other reducers and for the name `"communities"`, whose fit is not kept; `tests/test_features_info.py`). Summary columns constant up to round-off (range <= 1e-9 * max|column|, or <= 1e-12 of the largest absolute value of the unit's output) are set to their means and reported by the constant-output warning. Steps with a summary reducer, `null_combine` and `autofc`/`isfc`/`wisfc` are streamed in blocks of nodes. The original two-path pipeline of the paper is `rfun="PCA", delta_rfun=None, delta_weights_function=tc.eye_weights` (pinned by `tests/test_legacy_pipeline.py`); the decoders always use co-fluctuations on the feeding path. Causal mode (keyword-only `causal`, `min_samples`, `fit_timepoints` in `features` and `two_path_step`; `refit_every`, `return_model` in `features` only; all but `causal` raise `ValueError` without `causal=True`): `_check_causal` raises before anything is computed for what has no causal form (missing kernel parameters on either path or order, `eye_weights`, forward kernels, `cfun=tc.wisfc` without fixed weights, events given as features, a `min_samples` no kernel reaches), `_check_refit_every` validates `refit_every`; `_check_streamed_steps(..., causal=True)` also checks the steps streamed with fixed-weight `wisfc` before order 1 runs; every causal `features` call is run by `model._causal_features` (reducers that need no fit, None and graph measures, have nothing to fit there; a fitted reducer, the defaults included, requires `fit_timepoints`), with `_causal_step` passing the estimator's causal arguments to each step's `timecorr` call and `_fit_pass` silencing the estimator's row warnings during the fit. Causal `return_info` entries add `"weights_params"` and `"warmup_rows"` (`_warmup_rows`: rows entirely NaN; per subject for lists), fitted steps `"fit_timepoints"`, `"refit_rows"`, `"refit_kept_previous"`; `_constant_columns(out, causal=True)` ignores NaN rows; summary columns are not set to their means and no constant-output warning is issued; non-causal entries keep their exact key sets.
- **`timecorr/model.py`**: causal features with fitted reducers: `FeaturesModel` (exported as `tc.FeaturesModel`; returned by `features(..., causal=True, return_model=True)`; attributes `order`, `fit_timepoints`, `refits`, `fits` (`{(order, path): fit}`), `info`, `n_features`, `n_subjects`, the kernels, `cfun`, `combine`, `include_zero`, `min_samples`, `ndims`, settable `max_memory_gb`; `transform(data, return_delta=False, return_info=False, *, events=None)` runs the pipeline on other data with the fits frozen; picklable unless the call had a lambda or local function; a pipeline with a fitted summary needs the number of subjects of the fit). `features` with `causal=True` calls `_causal_features`; with a fitted reducer `_single_fit` runs the pipeline on the first `fit_timepoints` rows alone, order by order (pass 1: every reducer fitted on those rows, each order's fit reading the feeding features of those rows), and `_causal_pass` runs it on every row with the fits frozen (pass 2), so the fits of a series and of a longer one with the same first rows are bit-identical. `refit_every=m` (`_refit`) repeats both passes for the fits at rows `n + j*m` and stitches rows `[s_j, s_{j+1})` from pass 2 of fit `j` (rows before `n` from fit 0); the structure is that of fit 0 (`_refit_settings`: the automatic feeding step's choice, number of components, and the output columns of a communities step, its communities of 2 or more nodes; `_same_width`: a refit clusters with fit 0's number of clusters n0, then n0 + 1, n0 - 1, ... up to n0 +- 5 (`_REFIT_CLUSTER_RANGE`; between 2 and the number of nodes), and takes the first clustering with that many such communities; `_effective`: the `"effective"` entry of a `Communities(n=...)` step shows the number of clusters of the fit the entry describes), each reducer's fit is matched to the fit before as soon as it is made (`_Matched`, `_match_model`: assignment by largest sum of absolute cosines of `components_`, signs set to agree; `_match_labels`: communities by most shared nodes), and a fit that cannot have the structure (`helpers._FitUnusable`) is left out for every order (the fit before stays; its row is in `"refit_kept_previous"`, and one `UserWarning` per call names the rows left out and the step). The model holds the last fit; summary objects passed as reducers keep fit 0's records in `fits_`.
- **`timecorr/summaries.py`**: squared-correlation summaries `WeightedStrength` (weighted sums of squared correlations per node; `signed`, `split`; `center`: pair weights centered on the mean of their lower cluster (default), `"median"`, or `False`) and `Communities` (mean squared correlation within communities found by spectral k-means; `n=None` in `features` uses a shift null), with `fit`/`transform`/`fits_` (`transform(..., fit_index=...)` names the fitted unit of each unit), and the streaming engine used by `features`.
- **`timecorr/decoding.py`**: timepoint decoders (`timepoint_decoder`, `weighted_timepoint_decoder`, `weighted_timepoint_decoder_ec`, `pca_decoder`) and their helpers. - **`timecorr/events.py`**: event-restricted kernels: parsing of `events` specifications into boundary sets (`resolve_events`, `resolve_events_by_order`, `check_boundaries`, `block_labels`), `mask_kernel` (zero weight between timepoints in different blocks), `distinct_event_sets`, and `segment` (hidden Markov model segmentation with hmmlearn: `kind="ordered"`, with `n` given or chosen automatically, or `kind="recurring"`).

### Key Concepts

The `timecorr` function accepts:
- `data`: numpy array, pandas DataFrame or polars DataFrame (timepoints x features), or a list of them (one per subject)
- `weights_function` / `weights_params`: the kernel; row `t` of the kernel matrix (`weights[t, :]`) is the kernel used at timepoint `t`
- `include_timepoints` (`'all'`, `'backward'`/`'pre'`, `'forward'`/`'post'`), `include_zero`, `exclude_timepoints`: restrict the kernel
- `causal` / `min_samples` / `fit_timepoints` (keyword-only): the causal mode (below)
- `events` / `events_params`: restrict the kernel to blocks of consecutive timepoints (boundaries, features segmented with `segment`, or a per-subject list; in `features` and the correlation decoders also a dict keyed by order); also accepted by the decoders
- `cfun`: correlation function: `isfc` (each subject versus the others), `wisfc` (weighted), `autofc` (within subject), or `None` (smoothing)
- `combine`: how per-subject results are combined (`null_combine` keeps them separate)
- `rfun`: dimensionality reduction applied to the vectorized correlations (a model name, a graph measure, a summary such as `tc.WeightedStrength(signed=True)` or `"communities"`, or a callable); in `features` also `"auto"` (the default) and dicts keyed by order, with `delta_rfun` for the feeding path

The estimator (`wcorr`) is a kernel-weighted Pearson correlation; a true delta kernel (`eye_weights`) gives co-fluctuations (products of z-scored series). It reads every kernel (a T x T array or a `LagKernel`) through `helpers._KernelRows`, in chunks of 128 rows (`_kernels.CHUNK`), each a contiguous block over its columns, with one span finder (`_time_slices`, which also reads the prepared rows of `_KernelRows`) and one rescaling of extreme rows, so an array and the equal `LagKernel` give identical results (`tests/test_chunked_kernels.py`; `tests/test_kernels_reference.py` compares with stored outputs of commit 6b3d23a, written by `tests/fixtures/make_chunked_kernels_reference.py`); blocks are kept up to `_KERNEL_CACHE_ELEMENTS` (32 MB) and computed again beyond it, and the kernel memory of a `LagKernel` is at most that plus about 4 blocks of 128 x T (`_kernel_work_elements`, used by `estimate_memory_gb`, whose keyword `weights_function` counts a user's kernel function as T x T arrays). Its kernel products are time sliced: each chunk is multiplied only with the span of columns where it has non-zero weight, unless the spans cover more than half the kernel or the samples, their squares or cross products are not all finite; then each chunk spans every column (`helpers._TIME_SLICING = False` forces that; `tests/test_time_sliced_estimation.py` compares both). The two differ only in the order of floating-point summation, but entries whose kernel-weighted variance nearly cancels are sensitive to that order in either path, so the tests compare those entries by a conditioning measure computed from the data and kernel. A kernel-weighted variance counts as zero (correlations 0, counted in the zero-variance warning) when it is at most 1e-10 of the mean square of the globally centered column or at the round-off level of the raw column (`helpers._zero_variance` and `_round_off_variance`, also used by the delta kernel's and `segment`'s z-scores). Columns are centered on their overall means, so with a one-sided kernel only well-conditioned estimates are independent of the excluded timepoints; estimates near the 1e-10 threshold can differ (`tests/test_estimator_causality.py`). Fisher z averaging and `tstat_combine` treat values at most `helpers._UNIT_TOLERANCE` (128 eps, 2.8e-14) below +-1 or at most 1e-12 above as +-1 (`helpers._correlation_z`). `tstat_combine` gives an entry whose values across subjects have a range of at most `_UNIT_TOLERANCE` (128 eps, 2.8e-14), or that times the largest magnitude when it exceeds 1 (`helpers._round_off_spread`; absolute below 1, so values closer than 2.8e-14 are equal whatever their size, 1e-16 and 2e-16 included: a correlation's round-off is absolute, 0.19 eps measured for correlations below 0.01, up to 14,000 eps of their size), the value of an entry without spread: +-inf with the sign of the mean, 0 for a mean of 0 (p 0 or 1), in causal and non-causal mode; `isfc` of two subjects computes the same correlations in two orders, which differ by up to 61 eps (measured; more in the first defined row of causal mode, 3 samples, whose entries above the bound keep their finite statistic); `tests/test_round_off_variance.py`.

Causal mode (`causal=True`; `tests/test_causal_*.py`). The guarantee as documented: row `t` is unchanged bit for bit when rows after `t` are replaced by any values (finite, NaN, inf) and, with the built-in kernel functions, when they are removed (every reducer, combine function and `cfun=None` included; `test_removing_later_rows_changes_no_bit*` and `*_exact_under_removal` in `tests/test_causal_*.py`); with a kernel array or kernel function of the user's removal is documented to 1e-9 for outputs continuous in the correlations (no reduction, `"strength"`, the summaries, linear models once fitted), not for the eigenvector-based graph measures where leading eigenvalues coincide, to about 1e-9 of their magnitude for `tstat_combine` t statistics of nearly equal correlations, and for smoothed values to round-off relative to the data's magnitude (1e-9 or 8 units in the last place of the largest magnitude); with `include_zero=False` row `t` is also unchanged when row `t` changes; with a fitted reducer the guarantee is for rows `t >= fit_timepoints`, and a row before is unchanged when rows from `fit_timepoints` on change. The kernel is backward (`'forward'`/`'post'` raise) and its parameters must be given (`weights_params=None` raises for every kernel; `{}` for one without parameters); `eye_weights`, `cfun=tc.wisfc` (but not `functools.partial(tc.wisfc, subject_weights=...)`, recognized as the built-in with fixed weights), events given as features, and a kernel array or user kernel function with weight above the diagonal (`_check_causal_kernel`) raise `ValueError`; a callable `cfun`/`combine`/`rfun` of the user's runs with one `UserWarning` that the guarantee does not cover it (`timecorr._builtin_combine` names the built-in combine functions); `timecorr(causal=True, cfun=None)` ignores `rfun` as without `causal`; event boundaries at or beyond the end of the data are ignored, so a prefix runs with the events of the whole series, and every prefix from T = 1 runs. The estimator (`helpers._causal_setup`, `_causal_block`): `_causal_clean` turns inf and `|x| > 1e150` (`_CAUSAL_MAX`) into NaN; a timepoint without any sample gets zero kernel columns; a row is defined (`_causal_defined`) with at least 3 observed timepoints of non-zero weight and, with `min_samples` (default None), an effective sample size `(sum |w|)**2 / sum w**2` over them of at least `min_samples` (relative tolerance 1e-12; smoothing uses the effective size only, per feature; a number no built-in kernel row can reach raises, decided from the lag profile by `_kernel_reach` / `_check_reachable`, independent of T; for a Mexican hat wider than about 2 million samples the reach is an upper bound about 1% above, `_strided_reach` with `_STRIDED_MARGIN` 1.01), and undefined rows are NaN, the diagonal included (zero-variance entries stay 0); chunks are always time sliced and computed a group of 16 rows at a time (`_CAUSAL_GROUP`, larger for chunks weighting more than `_CAUSAL_SPAN` = 512 columns). What makes removal exact: no shape or operand of the operations that give a row depends on the length of the series or on the block of features asked for. `_causal_groups` gives every group the row count `n` and columns `c0:g0+n` it has in a complete chunk of a series without an end (`_group_block` and `_group_span` fill rows and columns beyond the data with zeros; the group size comes from `t0 + CHUNK - c0`, not from the chunk's last column); `_time_slices(always=True)` takes a `LagKernel` chunk's first column from `LagKernel.span` (that of its first row), not from its non-zero weights (a Mexican hat is exactly 0 at lag sigma); `_causal_block` computes the cross products of each row of features as one item of a stacked `np.matmul` (BLAS results of one 2-D product depend on which other rows and columns are in it; measured on Accelerate), the triangle of an autocorrelation in aligned sets of `_CAUSAL_FEATURES` = 8 rows of features with the columns from the set's first row on (`state["triangular"]`; `_wcorr_blocks` uses blocks that are multiples of 8; the streamed path of `_corr_row_blocks` uses every column), and `_causal_pairwise` the pairwise sums the same way; `_causal_smooth` pads each chunk to 128 rows and to the columns up to `t0 + CHUNK`; `_kernel_samples` sums the effective sizes of `min_samples` over the same columns; a causal streamed block (`_corr_row_blocks`) sets its diagonal and averages no pair with its transpose (`_symmetrize_block(average=False)`: the blocks of nodes depend on T and `max_memory_gb`, so the two orientations of a pair agree to round-off only); `_FittedModel._reduce` gives hypertools `_APPLY_ROWS` = 128 rows at a time, zero-filled. No causal output depends on `max_memory_gb`. All of it is tested, not proven (it needs a BLAS that computes a row of a product of fixed shape from that row alone; run with Accelerate so far): `tests/test_causal_removal_random.py` draws configurations (300 in every run, 3000 slow). Each group is centered on the kernel-weighted mean of the observed samples at its first row (`_group_reference`; without one, `_causal_reference`: the mean of the earlier observed samples in the span, else the first observed sample), never on the overall mean; a row uses the sums for complete data exactly when no timepoint it weights has a NaN sample and the pairwise sums otherwise, so later values change no bit; the zero-variance rule (`_causal_zero_variance`) is `_zero_variance` about the group's reference or a kernel-weighted standard deviation below 1e-9 (`_CAUSAL_CONSTANT`) of `|kernel-weighted mean|` (a column constant up to round-off, which causal mode does not set to its mean). `mat2vec` zeroes NaN above the diagonal, so code that vectorizes causal correlations has to put the NaN rows back. Reducers in causal mode skip NaN rows (fits use defined rows; transforms return NaN rows as NaN; a defined row is one without any NaN or infinite value, `timecorr._defined_rows`, for models, summaries and graph measures alike: hypertools imputes from every row it is given and the summaries raise for NaN, so a partly NaN row, as of smoothing in `features`, is left out of fits and is a row of NaN in the output; streamed steps without `max_memory_gb` use the block size of data with NaN samples for every recording (`summaries._Units.has_nan`), so later NaN samples change no bit; a model needs 2 defined training rows, a summary 1, the shift null 40 rows) and combine functions give NaN on the union of the subjects' NaN rows; at orders >= 2 the NaN rows of the feeding features are missing data, so warm-up accumulates over orders. Hypertools models: the guarantee covers `_GUARANTEED_MODELS` of `timecorr.py` (scikit-learn's PCA, IncrementalPCA, TruncatedSVD, FastICA, FactorAnalysis, by exact class); any other model whose fitted estimator has `components_`, reproduces its training rows to 1e-9 and reduces rows one at a time as together is used with one `UserWarning` per call (`_uncovered_model`, `_warn_uncovered_models`); a model without `components_` or failing a check raises `ValueError` (UMAP, KernelPCA, Isomap, MDS, TSNE, SpectralEmbedding, LocallyLinearEmbedding); `"PCA"` is fitted with `svd_solver="full"` unless a model dict gives a solver; `"FastICA"` is given the columns that vary on the training rows first (`helpers._varying_first`, `_FittedModel.order`; `components` are returned in the order of the input) and at most as many components as such columns (scikit-learn multiplies a component by the sign of its loading on the first column, a constant diagonal entry: 0 on some platforms, and the fit then holds NaN); a model output column constant on the training rows up to round-off (`_FROZEN_RTOL` 1e-9, `_FROZEN_ZERO_RTOL` 1e-12) is frozen: a value within that tolerance of the column's training mean is returned as that mean, other values as computed; a model asked for at least as many components as columns changes nothing (zero columns appended). The warning text about undefined timepoints counts rows of the whole output (ruled not part of the guarantee, which is about returned values).

### Data Flow

1. Inputs are formatted as float timepoints x features matrices (`format_data`)
2. The weights function builds the T x T kernel; the include/exclude options restrict it
3. The correlation function computes moment-by-moment correlations, vectorized with `mat2vec`
4. The combine function merges subjects; the reduction function reduces the number of features
5. `features` repeats this per order: the analysis path gives `X_k` from the delta (feeding) features `D_{k-1}`, and the feeding path (`autofc` with a Gaussian kernel whose width is set from the order's input by default, or the kernel in `delta_weights_function`; `eye_weights` gives the original pipeline's co-fluctuations) gives `D_k`, reduced by `delta_rfun` (default: `Communities()`)
