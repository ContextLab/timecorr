## About This Project

timecorr is a Python toolbox for computing and exploring correlational structure in timeseries data. The `timecorr` function computes kernel-weighted dynamic correlations from timeseries observations, and `features` computes higher-order dynamic correlations through the two-path pipeline of Owen, Chang & Manning (2021), Fig. 10 (by default with Gaussian kernels whose widths are set from each order's input and squared-correlation summaries at orders >= 2; the original pipeline is selected with `rfun="PCA", delta_rfun=None, delta_weights_function=tc.eye_weights`).

## Code Architecture

### Core Components

- **`timecorr/timecorr.py`**: the `timecorr()` function, the primary entry point for computing dynamic correlations (or, with `cfun=None`, kernel-weighted smoothing).
- **`timecorr/_kernels.py`**: `LagKernel`, the kernels of `timecorr`, `features`, `two_path_step`, the streamed summaries and the decoders for the built-in kernel functions: the lag profile (length T; the kernel functions in `helpers` build their T x T matrices from the same profile functions), `include_timepoints`/`include_zero`/`exclude_timepoints` and the event labels (`events.mask_kernel` accepts it), with `block(t0, t1, c0, c1)`, `span(t0, t1)` and `key(t0, t1)` (chunks away from edges and event boundaries share one block; `with_events` intersects the events it already has, `with_events(None)` keeps them; labels are runs of consecutive values, a single block stored as None; a non-finite `exclude` raises `ValueError`, as `exclude_timepoints` does for every kernel function); no T x T array is built (`uniform_weights` and `eye_weights` build their dense output directly). A kernel function of the user's gives T x T arrays (`helpers._lag_kernel` returns None for it), wrapped in `ArrayKernel` (the same `shape`/`chunks`/`block` interface; every chunk spans all columns; blocks are read-only views); `as_kernel` wraps either, and `blocks(kernel, size, transform, full)` is the one chunk iterator (blocks computed once per key), used by the estimator, the smoothing of `timecorr` and the row statistics. A custom `cfun` receives T x T arrays (counted by the memory guards and by `estimate_memory_gb(..., cfun=)`; a feeding kernel of the user's counts only at the orders whose feeding path runs).
- **`timecorr/helpers.py`**:
  - Kernel functions (`gaussian_weights`, `laplace_weights`, `eye_weights`, `mexican_hat_weights`, `t_weights`, `uniform_weights`, `boxcar_weights`) and `one_sided`
  - The estimator `wcorr` and correlation functions (`isfc`, `wisfc`, `autofc`)
  - Combine functions (`null_combine`, `corrmean_combine`, `mean_combine`, `tstat_combine`)
  - `reduce` (dimensionality reduction), `format_data` (input formatting via pydata-wrangler), `mat2vec`/`vec2mat`, `smooth`, `plot_weights`
  - Re-exports of the decoders from `decoding.py`
- **`timecorr/higher_order.py`**: the two-path pipeline: `features`, `two_path_step`, `estimate_memory_gb` (`streamed=True` for the peak of a streamed step; `combine=` counts the temporaries of the built-in combine functions, not of a function of your own). Keyword-only `delta_weights_function` / `delta_weights_params` set the kernel of the delta (feeding) path (default None: `gaussian_weights`, giving `autofc` correlations; `eye_weights` gives co-fluctuations). Kernel parameters of None (the defaults `weights_params=None`, `delta_weights_params=None`) with Gaussian kernels on both paths are automatic (`_auto_sd`, `_auto_params`): at each order the feeding kernel's standard deviation is 5 autocorrelation widths of that order's input, at least 5 rows and at most a hundredth of its rows or 5 rows, whichever is larger (so 5 below 500 rows), and the analysis kernel's is that or 10 rows, whichever is larger (white data: 10 and 5 at order 1, the fixed kernels of earlier versions, which are requested with `weights_params={"var": 100}, delta_weights_params={"var": 25}`; recordings of up to 1000 timepoints: at most 10 samples at every order). With no kernel parameters and no events given and two-sided kernels (`include_timepoints="all"`), `features` passes each order's feeding features on at every `floor(sd / 2)`-th row while at least 1000 rows remain and returns every output at all timepoints by linear interpolation (`return_info` entries of automatic kernels have `kernel_sd` and `sampling`). With another kernel function, or `eye_weights` on the feeding path, None is that function's own defaults. `weights_params` / `delta_weights_params` also accept order maps (dicts whose keys are all integers in 1..order; missing orders use the default; `two_path_step`, exported as `tc.two_path_step`, raises for one). `rfun` / `delta_rfun` accept `"auto"` (the defaults; analysis: PCA at order 1, `WeightedStrength(signed=True)` above; feeding: `Communities()`, which needs >= 4 features and T >= 40 (with more features than distinct shift-null lags in `[L, T - L]`, each lag is used for several features, balanced, and features sharing a lag keep their dependence in that surrogate; for a built-in kernel without events, one-sided restriction or `exclude_timepoints` (`summaries._stationary`) the null's squared correlations are averaged over every s-th timepoint, s the kernel's standard deviation rounded down for a Gaussian: `summaries._null_row_stride`; for any other kernel (arrays, kernel functions of your own, restricted kernels), over every timepoint); when its communities would emit fewer than 4 columns, the step emits `WeightedStrength(split=False, signed=False, center=False)` instead, one column per input feature, warning only when the shift null found no structure) and dicts keyed by order. `return_info=True` returns `(result, info)` with one dict per step and path (reducers requested and used, widths, community counts, fallback reason; no arrays, but lists of ints: `"constant_columns"` in every entry, the output columns with `np.ptp(x, axis=0) == 0` in the returned arrays (after the interpolation to all timepoints; one list per subject for list outputs; for feeding features that are not returned, in the rows computed), and `"labels"` in feeding entries, the community of each input column when the step's output columns are the communities of a `Communities` object (the default's included), None after a fallback, for other reducers and for the name `"communities"`, whose fit is not kept; `tests/test_features_info.py`). Summary columns constant up to round-off (range <= 1e-9 * max|column|, or <= 1e-12 of the largest absolute value of the unit's output) are set to their means and reported by the constant-output warning. Steps with a summary reducer, `null_combine` and `autofc`/`isfc`/`wisfc` are streamed in blocks of nodes. The original two-path pipeline of the paper is `rfun="PCA", delta_rfun=None, delta_weights_function=tc.eye_weights` (pinned by `tests/test_legacy_pipeline.py`); the decoders always use co-fluctuations on the feeding path.
- **`timecorr/summaries.py`**: squared-correlation summaries `WeightedStrength` (weighted sums of squared correlations per node; `signed`, `split`; `center`: pair weights centered on the mean of their lower cluster (default), `"median"`, or `False`) and `Communities` (mean squared correlation within communities found by spectral k-means; `n=None` in `features` uses a shift null), with `fit`/`transform`/`fits_` (`transform(..., fit_index=...)` names the fitted unit of each unit), and the streaming engine used by `features`.
- **`timecorr/decoding.py`**: timepoint decoders (`timepoint_decoder`, `weighted_timepoint_decoder`, `weighted_timepoint_decoder_ec`, `pca_decoder`) and their helpers. All four accept `events` / `events_params`, resolved once on the full subject list before the folds (per-subject entries follow their subject through the folds; segmentation does not advance NumPy's global random state): the correlation decoders restrict the analysis kernel at levels >= 1 and leave level 0 unchanged; `pca_decoder` restricts its level-0 smoothing kernel and takes one specification, not a dict by order.
- **`timecorr/events.py`**: event-restricted kernels: parsing of `events` specifications into boundary sets (`resolve_events`, `resolve_events_by_order`, `check_boundaries`, `block_labels`), `mask_kernel` (zero weight between timepoints in different blocks), `distinct_event_sets`, and `segment` (hidden Markov model segmentation with hmmlearn: `kind="ordered"`, with `n` given or chosen automatically, or `kind="recurring"`).
- **`timecorr/_lazy.py`**: `lazy_import`, which installs an optional dependency (hmmlearn; joblib, imageio-ffmpeg and IPython for the video helpers) with pip on first use; `TIMECORR_AUTO_INSTALL=0` turns installation off.
- **`timecorr/datasets.py`** (used as `tc.datasets`; its functions are not top-level names): `fetch(url, path, sha256=None, member=None)` (cached download through uniquely named `.part` files next to the target and an atomic replace, so concurrent calls for one target are safe; a relative path is under the cache root `cache_dir()`: `$TIMECORR_DATA`, default `~/timecorr_data`; a cached file is checked against `sha256` on every call), `story_listening(n_nodes=100, return_nodes=False)` (HTFA node weights of the story-listening data, `pieman/pieman_posterior_K700.mat`; intact participants, nodes varying in every participant, farthest-point selection; `n_nodes` outside 1..679, the nodes that vary in every participant, raises `ValueError`; `return_nodes=True` adds a dict with `centers`, `widths`, `index`, `varying`, `total`) and `industry_returns(start, end)` (log returns of the 49 Industry Portfolios, `french/49_Industry_Portfolios_daily_CSV.zip`; `attrs` has the file's first line, `"header"`, and the count of missing returns, `"missing"`). `tests/test_datasets.py` holds the loading code the tutorial notebooks had at commit f9db4af and requires equal arrays. Only runtime dependencies.
- **`timecorr/video.py`**: `render_video(draw, n_frames, path, fps=30, crf=23, hold=0, n_jobs=None, chunk_size=25, retries=0)` (`draw(frames, paths)` is called once per run of at most `chunk_size` consecutive frames in joblib worker processes, 3 or the usable cores by default; PNG frames in a temporary folder; `hold` appends copies of the last frame; with `retries`, workers are stopped after an error and new ones draw the frames whose files do not exist, again in runs of consecutive frames; the video is encoded under a temporary name next to the target and replaces it only on success; encoded with imageio-ffmpeg's ffmpeg, `-c:v libx264 -preset slow -crf <crf> -pix_fmt yuv420p -movflags +faststart`, byte for byte what the notebooks' own command gave: `tests/test_video.py`), `show_video(path, width=960)` (an HTML `<video>` tag with a relative, percent-encoded and escaped link inside a Sphinx source tree and for a URL; `IPython.display.Video(embed=True)` elsewhere) and `media_dir(name="tutorial_media")` (`../_static/tutorial_media` when the parent of the working directory holds `conf.py` and `_static`, otherwise `name`). All three are exported from `timecorr`.
- **`timecorr/tutorial.mplstyle`**: the plot style of the tutorials (`plt.style.use('timecorr.tutorial')`; the seven rcParams the notebooks set, the Okabe-Ito color cycle included; `package_data` in `setup.py`; needs matplotlib >= 3.7; `tests/test_tutorial_style.py`). Importing timecorr does not apply it.
- **`timecorr/simulate.py`**: simulated data with known dynamic correlations (`simulate_data`, `simulate_multi_order`) and helpers for structure embedded at a chosen order (`min_features`, `carrier_reducer`, `carrier_columns`, `nested_template`), and `simulate_nested` (nodes in modules in supergroups; returns `(data, truth)` with the order-2 signal `truth["h"]`), and `simulate_hierarchy` (nested groups of any depth `len(taus)`, one signal per group per level; returns `(data, truth)` with `truth["groups"]`, `truth["signals"]`, `truth["top"]` and the node signs `truth["signs"]`; `signs="private"` (default) or `"shared"`).

### Key Concepts

The `timecorr` function accepts:
- `data`: numpy array, pandas DataFrame or polars DataFrame (timepoints x features), or a list of them (one per subject)
- `weights_function` / `weights_params`: the kernel; row `t` of the kernel matrix (`weights[t, :]`) is the kernel used at timepoint `t`
- `include_timepoints` (`'all'`, `'backward'`/`'pre'`, `'forward'`/`'post'`), `include_zero`, `exclude_timepoints`: restrict the kernel
- `events` / `events_params`: restrict the kernel to blocks of consecutive timepoints (boundaries, features segmented with `segment`, or a per-subject list; in `features` and the correlation decoders also a dict keyed by order); also accepted by the decoders
- `cfun`: correlation function: `isfc` (each subject versus the others), `wisfc` (weighted), `autofc` (within subject), or `None` (smoothing)
- `combine`: how per-subject results are combined (`null_combine` keeps them separate)
- `rfun`: dimensionality reduction applied to the vectorized correlations (a model name, a graph measure, a summary such as `tc.WeightedStrength(signed=True)` or `"communities"`, or a callable); in `features` also `"auto"` (the default) and dicts keyed by order, with `delta_rfun` for the feeding path

The estimator (`wcorr`) is a kernel-weighted Pearson correlation; a true delta kernel (`eye_weights`) gives co-fluctuations (products of z-scored series). It reads every kernel (a T x T array or a `LagKernel`) through `helpers._KernelRows`, in chunks of 128 rows (`_kernels.CHUNK`), each a contiguous block over its columns, with one span finder (`_time_slices`, which also reads the prepared rows of `_KernelRows`) and one rescaling of extreme rows, so an array and the equal `LagKernel` give identical results (`tests/test_chunked_kernels.py`; `tests/test_kernels_reference.py` compares with stored outputs of commit 6b3d23a, written by `tests/fixtures/make_chunked_kernels_reference.py`); blocks are kept up to `_KERNEL_CACHE_ELEMENTS` (32 MB) and computed again beyond it, and the kernel memory of a `LagKernel` is at most that plus about 4 blocks of 128 x T (`_kernel_work_elements`, used by `estimate_memory_gb`, whose keyword `weights_function` counts a user's kernel function as T x T arrays). Its kernel products are time sliced: each chunk is multiplied only with the span of columns where it has non-zero weight, unless the spans cover more than half the kernel or the samples, their squares or cross products are not all finite; then each chunk spans every column (`helpers._TIME_SLICING = False` forces that; `tests/test_time_sliced_estimation.py` compares both). The two differ only in the order of floating-point summation, but entries whose kernel-weighted variance nearly cancels are sensitive to that order in either path, so the tests compare those entries by a conditioning measure computed from the data and kernel. A kernel-weighted variance counts as zero (correlations 0, counted in the zero-variance warning) when it is at most 1e-10 of the mean square of the globally centered column or at the round-off level of the raw column (`helpers._zero_variance` and `_round_off_variance`, also used by the delta kernel's and `segment`'s z-scores). Columns are centered on their overall means, so with a one-sided kernel only well-conditioned estimates are independent of the excluded timepoints; estimates near the 1e-10 threshold can differ (`tests/test_estimator_causality.py`). Fisher z averaging and `tstat_combine` treat values at most `helpers._UNIT_TOLERANCE` (128 eps, 2.8e-14) below +-1 or at most 1e-12 above as +-1 (`helpers._correlation_z`).

### Data Flow

1. Inputs are formatted as float timepoints x features matrices (`format_data`)
2. The weights function builds the T x T kernel; the include/exclude options restrict it
3. The correlation function computes moment-by-moment correlations, vectorized with `mat2vec`
4. The combine function merges subjects; the reduction function reduces the number of features
5. `features` repeats this per order: the analysis path gives `X_k` from the delta (feeding) features `D_{k-1}`, and the feeding path (`autofc` with a Gaussian kernel whose width is set from the order's input by default, or the kernel in `delta_weights_function`; `eye_weights` gives the original pipeline's co-fluctuations) gives `D_k`, reduced by `delta_rfun` (default: `Communities()`)

`tests/fixtures/chunked_kernels_reference.npz`), order-2 recovery on `simulate_nested` data (`test_nested_recovery.py`; its T 3000, isfc and K 702 cases are slow), kernels by order in `features` (`test_features_kernels_by_order.py`), `simulate_hierarchy` (`test_simulate_hierarchy.py`;
